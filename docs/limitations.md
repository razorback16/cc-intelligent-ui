# Limitations

← Back to the [README](../README.md)

- **Copying text from a picture** (refer to [Copy text from a picture](usage.md#copy-text-from-a-picture)) has these limits:
  - The automatic copy works on macOS and on Linux, but not over ssh (the clipboard tools of Claude Code run on the computer that runs Claude Code), and not in a background session. It needs the clipboard shims and `perl` (refer to [How it works](how-it-works.md)). With no `perl`, the mod makes no shims, and a copy keeps the picture cells. On Linux with no `wl-copy`, `xclip` or `xsel`, Claude Code copies with its own built-in code, which no shim sees. Then there is no automatic copy. `/iui details` shows the state on the line `Auto copy:`.
  - A shim asks only when Claude Code starts it directly. A clipboard tool that a different program starts (for example a script that runs `pbcopy`) gets its text with no change. The shim asks only for 4 MiB of text or less.
  - The `/iui grab` toast for picture cells that are not from this session needs a tool that tells the mod about each clipboard change. On macOS, this is `/usr/bin/perl` with Apple's PerlObjCBridge (macOS has it), which reads the change counter of the clipboard. On Linux, it is `wl-paste --watch` on Wayland, else `clipnotify` or GTK 3 from Python on X11 and Xwayland (refer to [Linux](install.md#linux)). If no such tool works, there is no toast: the mod does not read the clipboard at intervals in its place.
  - On GNOME with Wayland, `wl-paste --watch` does not work (GNOME does not have the data-control protocol). The mod then uses the X11 tools through Xwayland. This works on Ubuntu 24.04 with GNOME and Python GTK 3.
  - On Linux with the old `clipnotify` (1.0.2 or earlier), a mouse selection (the PRIMARY selection) also makes the mod read the clipboard once. The mod changes nothing in that case. When the automatic copy is off, the clipboard keeps the picture cells (U+10EEEE plus combining marks), and a paste gives strange characters. Use `/iui grab`, Claude Code's `/copy` (the last answer as Markdown, `/copy 2` for the one before it), or turn the mod off (`/iui off`) to select text.
  - The first copy from a page takes approximately 0.05 s for plain text (refer to [The lean font set](how-it-works.md#the-lean-font-set)), 0.15–0.5 s for other text, and 2–3 s for a page with a large Typst drawing. No toast shows during this time. If you paste before the toast "copied N chars of text" shows, the paste gives the picture cells.
  - The shim waits 1.5 s at most for the text, because Claude Code stops the clipboard tool after 2 s. When the mod needs more time (for example, the first copy from a large Typst drawing), the shim writes the picture cells. The mod does not write the text later, because a different session can copy the same cells in that time. A toast tells you to use `/iui grab`.
  - While the shim waits, the clipboard can have the picture cells from the OSC 52 copy of the terminal. If you copy something different in a different app in this time, the shim then writes the text over it.
  - If the terminal applies the OSC 52 copy after the clipboard tool wrote, the clipboard has the picture cells again. The mod does not write over them. Use `/iui grab`.
  - The mod copies whole words. It copies a word when the selection covers the middle of the word. In a code block, in a long word (30 characters or more, for example a path or a URL) and in CJK text, it copies each character whose middle is in the selection.
  - The mod does not copy math, the text in an image, or the text in a Typst drawing.
  - The cells do not identify the answer. The mod uses the answer of the selected row if it knows it, else the newest answer whose pages fit the selection. A selection in one page of a long answer fits each page that is tall enough, and the mod uses the first one. Thus the text can come from a different page or an older answer of the same width. `/iui dump` shows the page that the mod used.
  - The mod knows only the last 64 answers, plans or files that it drew in this session.
  - On the main screen (not fullscreen mode), there is no automatic copy. There the terminal copies the selection itself, not Claude Code, so no shim asks the mod. Two sessions can have the same picture cells. Thus the mod does not change the clipboard, and a toast tells you to use `/iui grab`. On the main screen, you must run `/iui grab` in the session that has the picture.
  - On the main screen, `/iui grab` does not know the row of the selection. Thus it can give the wrong text for a picture from before `/clear`, from a session that ended, or older than the last 64 pictures, and for a page after the first page of a long answer.
  - When a different session copies exactly the same cells less than 5 s after a copy of this session, the mod shows no `/iui grab` toast for it.
  - The mod makes the shims only in its own cache folder, and only when that folder, its `shims-<pid>` folder and its `ask` folder are folders of your user, not links, with no write access for other users. Else `/iui details` shows `Auto copy: off (the cache folder is not private)`.
  - In fullscreen mode, the mod does not change a copy of a selection that the terminal makes itself (for example, a drag with Option in iTerm2), because Claude Code does not see that selection. Select without the modifier key.
  - To stop the clipboard write on select, set `copyOnSelect` to `false` in `/config`. Then the mod does not copy a selection either, because Claude Code writes no copy that a shim can change. It changes only a clipboard that has picture cells (for example, after a copy with a key).
- **Picture select** (Claude Code 2.1.305 or newer, refer to [Picture select](usage.md#picture-select-claude-code-21305-or-newer)) has these limits:
  - It works only in fullscreen mode, and not over ssh (pages sent as bytes).
  - A selection is in one picture (an answer, a plan or a Markdown file, all its pages). A drag that starts on normal text and goes into a picture is the selection of Claude Code, which skips the picture. A drag that starts in a picture stays in that picture. Thus a selection of text and a picture together is not possible.
  - A click on normal text does not remove a picture selection. A click in a picture, a new picture selection or your next prompt removes it.
  - It has no double click (word) or triple click (line) selection, and no Shift+click to make a selection longer.
  - The highlight shows a short time after the first `down` on a page: the mod decodes the page one time (approximately 50 ms for a page of 3392 × 756 pixels, 200 ms for 3392 × 4284). Each frame is a new PNG that the terminal decodes (1.5 MB at most for the tallest page).
  - The highlight maps cells to pixels by the page's size in cells. If the terminal draws a page with space at its side or above (another aspect than its cells), the highlight can be off by part of a cell.
  - When Claude Code draws the page again from the start (for example, a page that scrolled far away and comes back), the page shows without its highlight until the selection changes. The copy is not changed.
  - The blue background is VS Code's selection colour, not the one of your terminal or Claude Code theme.
  - A page whose PNG is over 4 MiB (the most that the mod can read) has no highlight.
  - It needs `perl` (with `MIME::Base64`, a core module) to write the frames. With no `perl`, the selection and the copy work with no highlight.
- **Links in a picture:** a click on the picture does not open a link, because the mod cannot put a link on a picture. Use the link rows under the picture (refer to [Links, file paths and commands](usage.md#links-file-paths-and-commands)). A click on a command row copies the command only where Claude Code gets mouse clicks (fullscreen mode). A `file://` link opens in the app that the terminal chooses. A file row shows only when the file exists when the mod draws the answer.
- **PDF files** (refer to [What it draws](usage.md#what-it-draws)): a click on `‹`, `›` or the page number works only where Claude Code gets mouse clicks (fullscreen mode). The page field gets the keyboard only when the prompt is empty. If the prompt has text, the field opens without the keyboard: click the field to type. Then Esc goes to the prompt, not to the field. To close the field, click it and push Esc, or click its close mark. The mod draws one page at a time, and it does not show the number of pages. You cannot copy text from a PDF page.
- **The row grid** (`/iui grid on`, refer to [Selection and the row grid](usage.md#selection-and-the-row-grid)) has these limits:
  - Inline math that is taller than a row adds 1 row or more to its line. The text stays on the rows. Math that is only a little taller than the row does not add a row, and its ink can come near the line above or below.
  - At 100% text size, a level-1, level-2 or level-3 heading uses 3 rows. A level-2 or level-3 heading has 2 rows for the text and half a row above and below it. With a large text size (`/iui size`), a line uses 2 rows. A line of code uses 2 rows from approximately 111%. A line of body text uses 2 rows from approximately 117%. Then there is an almost empty row between the lines of a paragraph, and the picture starts half a row down. A heading or a code block is 1 row taller if its lines use an odd number of rows and a line of body text uses an even number of rows (or the opposite), because the mod moves its lines down by half a row. These values change with the terminal font and the cell size.
  - If an answer starts with a heading that has the half rows at 100% (for example, a level-3 heading), the first row of the picture is empty.
  - When a line of body text uses 2 rows, the rules of a table, display math, an image, a Typst drawing and a horizontal rule are half a row down. The text stays in the middle of the rows.
  - A level-4 to level-6 heading at 100% (and a level-3 or level-4 heading at approximately 117%) has the same gap above it and below it (1 row), because the two gaps are nearest to 1 row.
  - If inline math makes the first line of an answer taller, the reply bullet can be one row above the text.
- **Search does not find text in a picture.**
- **While Claude writes**, Claude Code shows its own text of the block (raw Markdown, for example `$…$` math as text), because Claude Code gives a mod the text of a block only when the block is complete. Then the block is blank until its picture is ready: approximately 0.03–0.07 s for plain text (refer to [The lean font set](how-it-works.md#the-lean-font-set)), 0.15–0.6 s for other text, and 2–3 s for a large Typst drawing. If the picture is not ready 2 s after the block is complete, the normal text shows until the picture is ready. If the compile fails, the normal text stays. An earlier answer that is not in the cache (for example, after a resume) is blank for up to 1 s, then shows as text until its picture is ready.
- **Short summaries** between tool calls stay as text.
- **Plan approval:** a mod cannot draw the Claude Code approval dialog, so the mod shows its own question. That question can have 4 options at most. Thus it has no option to keep planning (use Type something or Esc). The edit option cannot use a terminal editor (vim, nano), because a mod has no terminal. On Linux, it uses only the GUI editors that can wait until you close the file (refer to [Linux](install.md#linux)), not `xdg-open`. Where an organization manages Claude Code, `classic.PermissionRequest` hooks of a plugin that you install do not run. Then the Claude Code dialog shows after the mod's question.
- **Typst blocks:** `#page`, `#pagebreak` and `#set page` are errors. A package that is not in the mod cannot be downloaded (the network is blocked for Typst), so its block shows as code.
- **Security:** Typst runs with `--root /`, so a Typst block can read any file that you can read and draw it in the picture. Nothing leaves the computer.
- **The look is close to VS Code, not exact:** Typst does not use CSS. Raw HTML in Markdown is shown in a simple form or dropped. Loose lists have tight spacing (with `/iui grid on`, the items of a loose list have a gap of one row).
- **A picture that the terminal dropped from its image memory** (after many large pictures) is not sent again when you scroll back to it.
- **Over ssh**, the mod cannot read the terminal's config on your computer. So it uses the metrics of the theme's code font (Menlo on macOS) for the text size, and `auto` uses `COLORFGBG` if ssh sends it. Else `auto` is dark. The mod does not use the OS appearance of the remote computer. Pages are shorter, so that each one is at most 4096 pixels tall. In tmux or screen on the remote computer, no pictures show.
- **`auto` theme** reads the iTerm2 profile, the Ghostty, kitty and Rio configs, and the cmux settings directly. It does not read kitty's `globinclude`, `envinclude` and `geninclude` lines, or colours that you set while kitty runs. In other terminals, it uses `COLORFGBG` (set only when the terminal starts), then the OS appearance (on Linux, the desktop portal or GNOME's setting). If you change the theme of such a terminal and the OS appearance does not change, Intelligent UI does not see it. A change shows after up to 3 s.
