# Limitations

← Back to the [README](../README.md)

- **Copying text from a picture** (refer to [Copy text from a picture](usage.md#copy-text-from-a-picture)) has these limits:
  - Picture select is the copy for pictures. It works only in fullscreen mode, with Claude Code 2.1.298 or newer, and not over ssh. On the main screen, a copy gives picture cells (U+10EEEE plus combining marks), and a paste gives strange characters. Then use `/iui grab`, Claude Code's `/copy` (the last answer as Markdown, `/copy 2` for the one before it), or turn the mod off (`/iui off`) to select text.
  - The `/iui grab` toast for a copy of picture cells needs a tool that tells the mod about each clipboard change. On macOS, this is `/usr/bin/perl` with Apple's PerlObjCBridge (macOS has it), which reads the change counter of the clipboard. On Linux, it is `wl-paste --watch` on Wayland, else `clipnotify` or GTK 3 from Python on X11 and Xwayland (refer to [Linux](install.md#linux)). If no such tool works, there is no toast: the mod does not read the clipboard at intervals in its place. There is no toast over ssh or in a background session. `/iui details` shows the state on the line `/iui grab hint:`.
  - On GNOME with Wayland, `wl-paste --watch` does not work (GNOME does not have the data-control protocol). The mod then uses the X11 tools through Xwayland. This works on Ubuntu 24.04 with GNOME and Python GTK 3.
  - On Linux with the old `clipnotify` (1.0.2 or earlier), a mouse selection (the PRIMARY selection) also makes the mod read the clipboard once. The mod changes nothing in that case.
  - The mod finds the words of a page in the background when the page is on the screen. If they are not ready when you release the button (or when you run `/iui grab`), the copy takes approximately 0.05 s for plain text (refer to [The lean font set](how-it-works.md#the-lean-font-set)), 0.15–0.5 s for other text, and 2–3 s for a page with a large Typst drawing. Wait for the toast "copied N chars of text", then paste.
  - The mod copies whole words. It copies a word when the selection covers the middle of the word. In a code block, in a long word (30 characters or more, for example a path or a URL) and in CJK text, it copies each character whose middle is in the selection.
  - The mod copies inline math as its LaTeX source in dollars (for example `$A = \pi r^2$`), as one word: it copies the full equation when the selection covers the middle of the equation. If an inline equation breaks across two lines, select its first line. The mod does not copy display math (`$$…$$`), the text in an image, or the text in a Typst drawing.
  - For picture cells on the clipboard, the cells do not identify the answer. The mod uses the answer of the selected row if it knows it, else the newest answer whose pages fit the selection. A selection in one page of a long answer fits each page that is tall enough, and the mod uses the first one. Thus the text can come from a different page or an older answer of the same width. `/iui dump` shows the page that the mod used.
  - The mod knows only the last 64 answers, plans or files that it drew in this session.
  - The mod never changes the clipboard for a copy of picture cells: two sessions can have the same picture cells, and the mod cannot know which session a copy is from. A toast tells you to use `/iui grab`. Run `/iui grab` in the session that has the picture.
  - On the main screen, `/iui grab` does not know the row of the selection. Thus it can give the wrong text for a picture from before `/clear`, from a session that ended, or older than the last 64 pictures, and for a page after the first page of a long answer.
  - In fullscreen mode, a selection that the terminal makes itself (for example, a drag with Option in iTerm2) is not picture select, because Claude Code does not see it. It copies picture cells. Select without the modifier key.
- **Picture select** (Claude Code 2.1.298 or newer, refer to [Picture select](usage.md#picture-select-claude-code-21298-or-newer)) has these limits:
  - It works only in fullscreen mode, and not over ssh (pages sent as bytes).
  - On Claude Code 2.1.298 to 2.1.304, a selection that starts outside a picture (in the margin or the gutter, in normal text, or a double or triple click) is the selection of Claude Code, not picture select. It can copy picture cells (kitty placeholder characters) in place of the text of the picture. Then the mod shows the toast that names `/iui grab`. Run `/iui grab` to put the text on the clipboard. To use picture select, start the drag on the picture. From Claude Code 2.1.305, the selection of Claude Code skips picture cells, so such a selection copies no text of the picture.
  - A selection is in one picture (an answer, a plan or a Markdown file, all its pages). A drag that starts in a picture stays in that picture. Thus a selection of text and a picture together is not possible.
  - A single click on normal text (no drag, and no typing after it) does not remove a picture selection, because Claude Code tells a mod nothing about such a click. These remove it: a click in a picture, a new picture selection, a key typed in the prompt, a new selection of Claude Code (the mod looks for one every 0.25 s while a picture selection shows), your next prompt, and `/iui off` or `/iui select off`.
  - Escape does not remove a picture selection. Claude Code never gives Escape to a mod's region, and a region that takes keys would also take the keys that you type in the prompt after a click on a picture.
  - A selection of Claude Code (normal text) stays on the screen when you then drag over a picture: Claude Code removes its highlight only for a press outside a mod's region, and a mod cannot remove it. Its copy is done already. To remove it first, click normal text or push a key.
  - It has no double click (word) or triple click (line) selection, and no Shift+click to make a selection longer.
  - The mod gets a page ready for the highlight in the background, when the page is drawn or comes on the screen (refer to [The page cache](how-it-works.md#the-page-cache)). If you push the button on a page that is not ready, the highlight shows a short time later: the mod completes that page first (approximately 0.24 s of work for a page of 3392 × 4284 pixels, 0.045 s for 3392 × 756). Each frame is a new PNG that the terminal decodes (up to approximately 3 MB for a tall page). If you select many full rows of a page whose tinted rows are not ready, the highlight of those rows comes in some steps of one frame each.
  - The mod keeps the ready pages in memory, 128 MB (one page of 3392 × 4932 pixels uses approximately 74 MB). It drops only pages off the screen, the oldest first; it never drops a page on the screen or the page of the selection. If a page on the screen does not fit with the other pages on the screen, the mod does not make it ready in the background: it makes it ready at the next push of the button on it (then the memory can go over 128 MB for a short time). It makes a dropped page ready again when the page comes on the screen, or at the next push of the button on it.
  - The highlight maps cells to pixels by the page's size in cells. If the terminal draws a page with space at its side or above (another aspect than its cells), the highlight can be off by part of a cell.
  - When Claude Code draws the page again from the start (for example, a page that scrolled far away and comes back), the page shows without its highlight until the selection changes. The copy is not changed.
  - The blue background is VS Code's selection colour, not the one of your terminal or Claude Code theme.
  - A page whose PNG is over 4 MiB (the most that the mod can read) has no highlight.
  - A click on a link, a file path or a command (refer to [Click a link, a file or a command](usage.md#click-a-link-a-file-or-a-command)) has these limits:
    - A click copies. It does not open a link or a file: the terminal does not send cmd+click to Claude Code, and on macOS ctrl+click is the secondary click.
    - A code block is not a target, also a `bash` block. To copy a command in a code block, select its text. The dim rows under the picture (with a copy button for a `bash` block) do not show with picture select.
    - The mod finds the targets from the words of the page. Until they are known (the probe, refer to [The page cache](how-it-works.md#the-page-cache)), a hover shows no highlight, and a click waits for them.
    - A file path is a target only when the file exists when the mod draws the answer. A link to a heading of the same text is not a target. A link, a file path or a command in a Typst drawing, in math or in an image is not a target.
  - It needs `perl` (with `MIME::Base64`, a core module) to write the frames. With no `perl`, the selection and the copy work with no highlight (the mod tries one time, then writes the reason to the debug log).
- **The cache folder:** the mod uses only its private cache folder (`$TMPDIR/cc-intelligent-ui-<uid>`, mode 700, your own and not a link). If that folder is a link, is not a folder or is not yours, the mod draws nothing and picture select is off. `/iui`, `/iui details` and a toast at the start tell you why. Remove or fix that folder, then start Claude Code again.
  - It copies at the button's up, also when `copyOnSelect` is `false` in `/config`.
- **A fake bold** (a terminal font with no bold face, for example Monaco): bold text gets a thin outline in its colour. These limits apply:
  - A character that the terminal font does not have (for example, CJK text in Monaco) comes from another font. If that font has a bold face, the character gets both the real bold face and the outline, so it is a little bolder than in the terminal.
  - Bold text in a live Typst drawing (for example, `text(weight: "bold", font: theme.mono)`) does not get the fake bold. It shows as regular text.
- **Links in a picture:** without picture select (the main screen, over ssh, Claude Code before 2.1.298, `/iui select off`), a click on the picture does not open a link, because the mod cannot put a link on a picture. Use the link rows under the picture (refer to [Links, file paths and commands](usage.md#links-file-paths-and-commands)). A click on a command row copies the command only where Claude Code gets mouse clicks (fullscreen mode). A `file://` link opens in the app that the terminal chooses. A file row shows only when the file exists when the mod draws the answer.
- **PDF files** (refer to [What it draws](usage.md#what-it-draws)): a click on `‹`, `›` or the page number works only where Claude Code gets mouse clicks (fullscreen mode). The page field gets the keyboard only when the prompt is empty. If the prompt has text, the field opens without the keyboard: click the field to type. Then Esc goes to the prompt, not to the field. To close the field, click it and push Esc, or click its close mark. The mod draws one page at a time, and it does not show the number of pages. You cannot copy text from a PDF page.
- **The row grid** (`/iui grid on`, refer to [Selection and the row grid](usage.md#selection-and-the-row-grid)) has these limits:
  - Inline math that is taller than a row adds 1 row or more to its line. The text stays on the rows. Math that is only a little taller than the row does not add a row, and its ink can come near the line above or below.
  - At 100% text size, a level-1, level-2 or level-3 heading uses 3 rows. A level-2 or level-3 heading has 2 rows for the text and half a row above and below it. With a large text size (`/iui size`), a line uses 2 rows. A line of code uses 2 rows from approximately 111%. A line of body text uses 2 rows from approximately 117%. Then there is an almost empty row between the lines of a paragraph, and the picture starts half a row down. A heading or a code block is 1 row taller if its lines use an odd number of rows and a line of body text uses an even number of rows (or the opposite), because the mod moves its lines down by half a row. These values change with the terminal font and the cell size.
  - If an answer starts with a heading that has the half rows at 100% (for example, a level-3 heading), the first row of the picture is empty.
  - When a line of body text uses 2 rows, the rules of a table, display math, an image, a Typst drawing and a horizontal rule are half a row down. The text stays in the middle of the rows.
  - A level-4 to level-6 heading at 100% (and a level-3 or level-4 heading at approximately 117%) has the same gap above it and below it (1 row), because the two gaps are nearest to 1 row.
  - If inline math makes the first line of an answer taller, the reply bullet can be one row above the text.
- **Search does not find text in a picture.**
- **While Claude writes**, Claude Code shows its own text of the block (raw Markdown, for example `$…$` math as text), because Claude Code gives a mod the text of a block only when the block is complete. Then the block is blank until its picture is ready: approximately 0.03–0.07 s for plain text (refer to [The lean font set](how-it-works.md#the-lean-font-set)), 0.15–0.6 s for other text, and 2–3 s for a large Typst drawing. If the picture is not ready 2 s after the block is complete, the normal text shows until the picture is ready. If the compile fails, the normal text stays. An earlier answer that is not in the cache (for example, after a resume) is blank for up to 1 s, then shows as text until its picture is ready.
- **Short summaries** between tool calls stay as text.
- **Plan approval:** a mod cannot draw the Claude Code approval dialog, so the mod shows its own question. That question can have 4 options at most. Thus it has no option to keep planning (use Type something or Esc). The edit option cannot use a terminal editor (vim, nano), because a mod has no terminal. On Linux, it uses only the GUI editors that can wait until you close the file (refer to [Linux](install.md#linux)), not `xdg-open`. Where an organization manages Claude Code, `classic.PermissionRequest` hooks of a plugin that you install do not run. Then the Claude Code dialog shows after the mod's question.
- **Typst blocks:** `#page`, `#pagebreak` and `#set page` are errors. A package that is not in the mod cannot be downloaded (the network is blocked for Typst), so its block shows as code.
- **Security:** Typst runs with `--root /`, so a Typst block can read any file that you can read and draw it in the picture. Nothing leaves the computer.
- **The look is close to VS Code, not exact:** Typst does not use CSS. Raw HTML in Markdown is shown in a simple form or dropped. Loose lists have tight spacing (with `/iui grid on`, the items of a loose list have a gap of one row).
- **A picture that the terminal dropped from its image memory** (after many large pictures) is not sent again when you scroll back to it.
- **Over ssh**, the mod cannot read the terminal's config on your computer. So it uses the metrics of the theme's code font (Menlo on macOS) for the text size, and `auto` uses `COLORFGBG` if ssh sends it. Else `auto` is dark. The mod does not use the OS appearance of the remote computer. Pages are shorter, so that each one is at most 4096 pixels tall. In tmux or screen on the remote computer, no pictures show.
- **In herdr**, herdr does not send an image to the terminal if the image is too large for its transfer limit (30 MiB as base64, approximately 22 MiB as pixels: width × height × 4 bytes). It shows no image and no message. Thus the mod makes pages shorter in herdr, so that each page is at most 16 MiB as pixels. A pasted image, an image that Claude sends, a PDF page or a live Typst drawing larger than approximately 22 MiB as pixels (for example, 2900 × 2000 pixels) does not show in herdr. With the `auto` theme, the background comes from herdr (the terminal in front). Claude Code sometimes reads herdr's answer first; then the mod keeps the last background for up to 2 more checks, after which it uses the terminal's config. The font comes from the herdr client where you typed last. With two terminals attached, the mod follows the terminal where you typed last, not the terminal that you look at. A change shows after the next check (up to 3 s; on Linux, the tty times change only about every 8 s, so it can take up to approximately 11 s). With `herdr --remote`, the client is on a different computer, so the mod does not find it and uses no terminal font, as over ssh. If the mod cannot read the processes (`ps`), it uses the variables of the terminal that started the herdr server. With more than one herdr server (named sessions), the mod uses `lsof` to find the clients of its own server; on Linux, `lsof` does not show this, so the mod can use a client of a different session.
- **`auto` theme** reads the iTerm2 profile, the Ghostty, kitty and Rio configs, and the cmux settings directly (in herdr, those of the terminal that herdr runs in). It does not read kitty's `globinclude`, `envinclude` and `geninclude` lines, or colours that you set while kitty runs. In other terminals, it uses `COLORFGBG` (set only when the terminal starts), then the OS appearance (on Linux, the desktop portal or GNOME's setting). If you change the theme of such a terminal and the OS appearance does not change, Intelligent UI does not see it. A change shows after up to 3 s.
